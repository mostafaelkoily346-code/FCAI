# تقرير مشروع موقع كلية الحاسبات والذكاء الاصطناعي

**تاريخ التقرير:** 5 نوفمبر 2026  
**الحالة:** يعمل محليًا، ومجهز مبدئيًا للنشر بالحاويات؛ لم يُنشر على الإنترنت.

## 1. ملخص تنفيذي

المشروع موقع عربي/إنجليزي لعرض معلومات كلية الحاسبات والذكاء الاصطناعي بجامعة بني سويف، مع خادم Node.js وواجهة API وقاعدة SQLite ولوحة إدارة. تسجيل الدخول والصلاحيات وتخزين الطلبات تعمل محليًا، واختبارات الخادم الـ11 ناجحة.

لا يوجد حاليًا رابط عام للموقع. مجلد المشروع ليس مستودع Git، ولا يوجد تسجيل دخول إلى GitHub في المتصفح، كما أن أدوات Docker وGitHub CLI غير متاحة. كذلك لم يُحدد نطاق جامعي أو خادم استضافة. لذلك لا يمكن اعتبار المشروع منشورًا أو جاهزًا لاستقبال بيانات طلاب حقيقية.

## 2. مكونات الموقع

- واجهة عربية/إنجليزية مبنية بـ HTML وCSS وJavaScript دون إطار واجهات أو حزم تشغيل خارجية.
- خادم Node.js يقدم ملفات الموقع وواجهات REST من المصدر نفسه.
- قاعدة SQLite عبر وحدة `node:sqlite` المدمجة في Node.js؛ الحد الأدنى المطلوب Node.js 22.13.
- صفحات ومحتوى للأخبار والمشاريع والمكتبة والمعرض والجداول والقيادة.
- صفحة تسجيل الطلاب ودخول المستخدمين ولوحة للإدارة.
- المعرض وبعض ملفات أعضاء الهيئة والمشاريع بيانات توضيحية/وهمية، وليست سجلات رسمية أو صورًا فوتوغرافية موثقة.

## 3. الباك إند والوظائف

- إنشاء حساب طالب بحالة «قيد المراجعة»؛ لا يستطيع الحساب دخول وظائف الطالب قبل موافقة المدير.
- تسجيل دخول وخروج وجلسات محفوظة في قاعدة البيانات وتنتهي بعد 8 ساعات.
- إدارة المدير لحسابات المستخدمين وطلبات التواصل/التدريب والشكاوى والاقتراحات وحالة كل طلب.
- تخزين الطلبات والمستخدمين والمحتوى القابل للتحرير في SQLite.
- واجهة API موثقة في [API.md](./API.md).
- إنشاء مدير لأول مرة أو تغيير كلمة مروره من أوامر محلية تفاعلية؛ لا توجد كلمة مرور افتراضية مضمّنة في الشيفرة.

## 4. الحماية الحالية

- تخزين كلمات المرور باستخدام `scrypt` بدل النص الصريح.
- ملفات جلسات تعريف الارتباط `HttpOnly` و`SameSite=Strict`؛ وتُضبط `Secure` عند التشغيل خلف وكيل HTTPS موثوق.
- فحص دور المدير على الخادم قبل إتاحة عمليات لوحة الإدارة.
- التحقق من مدخلات الطلبات، وفحص `Origin` لطلبات التعديل عند وجوده، وتحديد معدل بعض الطلبات العامة.
- ترويسات أمان لتقديم الملفات الثابتة، وعدم إتاحة ملفات قاعدة البيانات عبر خادم الموقع.
- الخادم المحلي يستمع افتراضيًا على `127.0.0.1`. لا ينبغي كشفه مباشرة للإنترنت.

هذه الخصائص ونجاح الاختبارات لا يعادلان تدقيقًا أمنيًا مستقلًا أو اعتمادًا مؤسسيًا.

## 5. قاعدة البيانات والبيانات التجريبية

ملف قاعدة البيانات المحلية هو `backend/data/fcai.sqlite`، وهو مستثنى من Git. يحتوي المشروع على بيانات أولية تُحمّل عند إنشاء قاعدة جديدة، ومنها شكاوى تجريبية معلّمة. التسجيلات والطلبات الحقيقية لا تُضاف كبذور وهمية. تعديل ملفات JSON بعد إنشاء القاعدة لا يحدّث تلقائيًا البيانات الموجودة داخلها.

يجب عدم نشر ملف SQLite المحلي أو نسخه إلى مستودع عام. يلزم تحديد سياسة نسخ احتياطي واستعادة وصلاحيات وصول قبل استخدام قاعدة إنتاج.

## 6. التشغيل والاختبار محليًا

يتطلب التشغيل Node.js 22.13 أو أحدث:

```powershell
npm start
```

ثم افتح `http://127.0.0.1:8080`. لإنشاء أول مدير على جهاز موثوق:

```powershell
npm run admin:create -- --email admin@fcai.local
```

ولتغيير كلمة مرور المدير من طرفية تفاعلية:

```powershell
npm run admin:password -- --email admin@fcai.local
```

لا تُرسل كلمة المرور إلى المحادثات ولا تضعها في ملفات المشروع أو GitHub.

**نتيجة التحقق في بيئة التطوير:** `npm test` نجح؛ 11 اختبارًا، دون إخفاقات. إصدار Node المستخدم وقت الفحص `v24.20.0`. هذه نتيجة اختبارات محلية وليست قياسًا لأداء خادم إنتاج.

## 7. النشر المقترح ومتطلباته

يتضمن المشروع `Dockerfile` و`compose.yaml` و`Caddyfile` لتشغيل التطبيق خلف وكيل Caddy مع HTTPS، مع تخزين دائم منفصل لقاعدة البيانات. لم يتم بناء الحاويات أو اختبارها هنا لأن Docker غير متاح.

يلزم قبل الحصول على رابط عام:

1. مستودع GitHub يملكه المستخدم، مع تحديد ما إذا كان عامًا؛ موافقة المستخدم السابقة كانت على نشر الشيفرة علنًا.
2. تسجيل الدخول إلى GitHub وإنشاء المستودع أو تفويض أداة النشر. لا ترسل كلمة المرور أو رمز الوصول في المحادثة.
3. استضافة Linux/Docker مع مساحة دائمة لقاعدة SQLite، أو خادم معتمد من الكلية.
4. نطاق تملكه/تعتمده الكلية، وضبط DNS وفتح المنافذ 80 و443 للحصول على HTTPS.
5. موافقة الكلية على المحتوى، وإشعار الخصوصية، والبيانات المسموح جمعها، والنسخ الاحتياطي والاستعادة والمراقبة.
6. إنشاء حساب المدير على الخادم الإنتاجي وتخزين بياناته في مدير أسرار معتمد.

تفاصيل النشر وقائمة القبول قبل الإطلاق في [DEPLOYMENT.md](./DEPLOYMENT.md). GitHub Pages وحده لا يشغل خادم Node.js أو SQLite، ولذلك لا يكفي لنشر المشروع كاملًا.

## 8. نواقص وحدود يجب إعلانها

- لا يوجد رابط استضافة عام أو مستودع GitHub مربوط حتى تاريخ التقرير.
- لا يوجد تسجيل دخول جامعي موحد أو تحقق فعلي من هوية/قيد الطالب؛ التسجيل يعتمد بيانات يدخلها المستخدم ثم موافقة المدير.
- لا توجد استعادة كلمة مرور آلية أو تحقق بريد إلكتروني أو رفع ملفات.
- البيانات الوهمية والصور التوضيحية تحتاج استبدالًا أو اعتمادًا رسميًا قبل عرض الموقع باعتباره موقعًا رسميًا.
- قاعدة SQLite أحادية العملية؛ ملاءمتها لحجم الاستخدام المطلوب تحتاج تقييمًا واختبار حمل على الخادم المستهدف.
- يلزم تدقيق أمني مستقل ومراجعة قانونية/خصوصية وإتاحة قبل استقبال بيانات حقيقية.
